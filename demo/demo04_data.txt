:= Master System について
:
  * マークIIIをベースに海外向けとして1986年発売
:
  * CPUはZ80 @ 3.58MHz
:
  * 8KBメインRAM、16KB VRAM
:
  * ソフトウェアはROMで提供される
:
  * ROMはRAMと同じアドレススペースでアクセスできる

    ただし書き込めない

  * PSG音源と(日本国内版のみ)FM音源を搭載
:
  * 本体デザインはカッコイイ

:
      スペック比較

MacBook (M1)      MasterSystem

64bit 8x 3.2GHz   8bit 3.58MHz

32GB RAM          8KB RAM

2560x1600         256x192

500GB SSD         32KB~ ROM

macOS             OSなし

  (ROMはバンク切替で512KBまで拡張可)

:= Z80について
:
  * 8-bit CPU
:
  * 1976-2024
:
  * 16ビットと8ビットのレジスタ
:
  * ある機能

    Fレジスタ、BCD命令、裏レジスタなど
:
  * ない機能

    割り算、掛け算、浮動小数点


:= mrubyとVM
:
  * mruby: 組み込みに適した軽量Ruby
:
  * Virtual Machine (仮想マシン)

:
  * RubyはmrubyでもCRubyでも
    バイトコードにコンパイルされてから実行される
:
  * VMがバイトコードを実行

:= バイトコード紹介

  Ruby:
:
    return 3 == 2
:
  Bytecode:
:
  1 000 {hl}LOADI_3    R1{hl}
  1 002 {hl}LOADI_2    R2{hl}
  1 004 {hl}EQ         R1    R2{hl}
  1 006 {hl}RETURN     R1{hl}
  1 008 {hl}STOP{hl}

:
  これをCのヘッダに書き出してVMと一緒にコンパイル

:= プラットフォームの制限

:
  * 8ビットで3.58MHzは遅い

:
  * 乗算も除算もソフトウェア実装
:
  * 乱数も実はコストが高い
:
  * ビットシフトも1ビットずつ(か8ビット)
:
  * 対策

    {hl}できることは事前計算で{hl}

:
  * 時計がない
:
    SDKがVSyncのカウントを提供している(60/s)

:= その他設計方針

:
  * サイズは基本固定

    現段階の例
    52個のレジスタ、16コールフレーム、
    8個のトップレベルメソッド

    コンパイル時に決めて、超えたらクラッシュ

:
  * エラーが出たらすぐクラッシュする

:
  * できることはビルド時にやる(事前計算)

:
  * Rubyで遅い場合はCで実装も

:= 小さくまとめる設計

:
  * Classとかは未実装

:
  * < オペレータは未実装

    {hl}a <= b{hl} -> {hl}b > a or b == a{hl}

:
  * floatなし
:
    つまり400 / 500 * 100 = 0
:
    順序を変えて計算

    (400 * 100) / 500
:
    ところがint16_tは-32768から32767まで
    なのでオーバーフロー
:
  * Exceptionなし

    エラーはクラッシュ
:
  * GCなし

    アロケーションを避ける

    (Stringは改変不可など)

:= 日本語表示について
:
  * 今回約250種の文字から約440種にサポートを拡大した
:
  * マスターシステムはタイルベースのグラフィック
    (最大448タイル)
:
  * 1バイトで1文字とした
:
  * 約250種の文字に収めるため「使う字だけ持ってくる」
:
  * オレオレエンコーディングになる
:
  * 今回9ビットで1文字とした。正直気持ち悪い
:
  * 16ビットでもできるが無駄が多い

    ROM容量は限られている
:
  * ひたすら詰め込んでRAMに展開するとRAMが足りない
:
  * 9バイトで8文字という変則エンコーディング

:= AOTコンパイラー
:
  * 高速化がしたかった
:
  * 単に最近流行っているのでやってみたかった
:
  * ただ、RubyからCは色々足りない(Parserなど)
:
  * バイトコードからCのAOTコンパイラ
:
  * 基本コーディングエージェント任せ(最近の流行)

:= AOTコンパイラー
:
  * 事前計算
:
  * fetch, decode,
    dispatch, execute

    dispatchまではビルド時にできる
:
  * type inferenceなどはしていない

:= AOTコンパイルの例
:
Ruby:
  {hl}3 == 2{hl}

:
バイトコード
  {hl}LOADI_3    R1{hl}
  {hl}LOADI_2    R2{hl}
  {hl}EQ         R1    R2{hl}
  {hl}RETURN     R1{hl}
  {hl}STOP{hl}

:
AOTの生成するC
  {hl}aot_loadi(vm, 1, 3);{hl}
  {hl}aot_loadi(vm, 2, 2);{hl}
  {hl}aot_eq(vm, 1);{hl}
  {hl}*rval = regs[1];{hl}
  {hl}return;{hl}

:
  さらに最適化もできるがしていない
