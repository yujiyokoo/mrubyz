# demo04 パック9bitテキストエンコーディング 設計ドキュメント

日付: 2026-07-15
対象: mrubyz / demo04 (Kansai RubyKaigi 9 プレゼンテーション)

## 背景と目的

demo04 のテキストは現在 1文字 = 1バイト (フォントタイル index 0–255) で、
グリフ上限が実質 255。Kansai RubyKaigi 9 のデッキは日本語主体になるため、
かな (~170) + ASCII (~95) だけで上限に迫り、漢字がほぼ入らない。

SMS のネームテーブル語はタイル index を **9 bit** 持てる (highlight が既に
同じ語の bit 11 を使用中)。VRAM のタイル実数は 448 で、demo04 は sprite が
446–447 を使うので、フォントの実用上限は index 445 まで
(予約値を除き **実質 442 グリフ**)。

1文字 2 バイトにするとテキスト容量が倍増して許容できないため、
**8文字を9バイトに詰める** (1.125 バイト/文字)。日本語主体テキストでは
可変長方式より予測可能で小さい。

成功条件: **既存の demo04 コンテンツが新エンコーディングでビルドでき、
表示が従来と同一である** (デッキ内容の書き換えは本設計のスコープ外)。

## ワイヤフォーマット: マスクバイト方式ブロック

テキストは 9 バイトブロックの列。ビットストリーム詰めではなく:

```
ブロック = [mask][low0][low1][low2][low3][low4][low5][low6][low7]
文字 i のコード = low_i | (((mask >> i) & 1) << 8)
```

- 9 bit コード = フォントタイル index そのもの (現行と同じ 1:1 対応)。
  ASCII は `ord` の位置に固定、割当グリフはその上を埋める。
  使用可能 index は 1–445 (446/447 は demo04 の sprite が使用)。
  予約値: `0x000`・`0x001` (hl)・`0x00C` (SMS stdio の FF/CLS 対策で現行
  どおり予約継続)・`0x00D` (改行)。**割当可能グリフ数は実質 442**。
- 制御コード (値は現行踏襲):
  - `0x001` — highlight トグル (タイル語に 0x0800 を OR、bit 11 =
    スプライトパレット選択。9 bit index とはビットが重ならない)
  - `0x00D` — 改行
  - `0x1FF` — **PAD**: 何もしない。converter が各アイテム末尾のブロックを
    これで埋める (タイル index 最大 445 と衝突しない)
- **パック単位はアイテム文字列 `pres_data[i][j]`** (ページではない)。
  ページは A ボタンで 1 アイテムずつ表示される文字列の配列であり、
  逐次表示を保つため各アイテムが独立に整数個のブロックになる。
  アイテムあたり平均 ~5 バイトの PAD オーバーヘッドは許容する。
  ブロック途中の PAD も無視する (デコーダは値で判定するので位置を問わない)。
- **センチネル文字列はパックしない**: `demo04.src.rb` は
  `pres_data[i][j] == "VMRUN\r"` の比較でライブ VM デモページを起動する。
  この種のセンチネル (converter に許可リストとして持つ: 現状 `"VMRUN\r"`
  のみ) とコマンド文字列 (`-colour1-` 等、既存 COMMAND_PATTERN) は raw の
  まま出力し、src.rb 側が puts_packed に渡す**前に**インターセプトする。
  原則: **パック文字列を `==`/`eql?` で比較してはならない** (op_eq は
  strcmp ベースで、パックデータの 0x00 バイトで誤動作するため)。
  比較対象になる文字列は必ず raw に保つ。

デコードは Z80 でシフト1回+OR のみ。低バイトは hex ダンプでそのまま
読めるためデバッグ性も現行に近い。

## VM 側の変更

### mrbz_val: 文字列に長さを持たせる

パックデータは正当に 0x00 バイトを含む (例: 全 ASCII ブロックの mask は
0x00) ため、現行 `puts`/`print` の NUL 終端走査は使えない。文字列長を
値に持たせる:

```c
union {
  int16_t intval;
  char* strval;
  struct { char* ptr; uint16_t len; } str;  // strval と ptr はエイリアス
  mrbz_array arrval;
  ...
} u;
```

- `op_string` が pool エントリの 2 バイト長 (big-endian、データ直前) を
  読んで `u.str.len` に格納する。これで mrubyz.c の
  `// TODO: Add length to mrbz value` が正式に解消される。
- union 最大メンバが 3→4 バイトになり、mrbz_val は +1 バイト。
  レジスタプール 52 個で **約 52 バイトの RAM 増** (8KB の 0.6%)。
  既存の `u.strval` 利用箇所は `str.ptr` とエイリアスなので無変更で動く。

### 新 builtin `puts_packed`

- 既存 `puts`/`print` は**無変更** (demo01–06、整数表示はそのまま)。
- T_STRING 以外の引数はエラー表示して exit (既存 builtin の慣例に従う)。
- `u.str.len / 9` ブロックを順に処理。1文字ごとの画面出力 (カーソル進行、
  32桁折返し、text_scroll、highlight 状態、改行) は `puts` と**同一挙動**
  でなければならないので、共通部分を static ヘルパに抽出して両者が呼ぶ
  (実装を2系統に分岐させない)。
- タイル語書込みは現行同様 `SMS_setTileatXY(x, row, tile)`。tile が
  9 bit になるだけで、highlight の `| 0x0800` とは干渉しない。

## ビルドパイプラインの変更

- **scripts/font_builder.rb**: index 上限 255 → **445** (0x00C は現行
  どおり予約継続、割当可能 442 グリフ)。ビルド時に総グリフ数・漢字数・
  残り予算を必ず表示し、超過時は超過グリフの一覧を出して**ハードエラー**。
- **scripts/converter.rb**: `encode_string` が 9 bit コード列を返し、
  新設の `pack_blocks` がマスクバイト方式で 9 バイトブロック列に変換、
  末尾ブロックを PAD (0x1FF) で充填する。パック単位はアイテム文字列。
  コマンド文字列 (`-colour1-` 等) とセンチネル (`"VMRUN\r"` 許可リスト)
  は raw のまま。`{hl}` マークアップの扱いは現行どおり (0x001 として符号化)。
- **demo/demo04.src.rb**: アイテム表示呼出し (3 箇所の
  `puts pres_data[i][j]`) が `puts_packed` になる。`"VMRUN\r"` 等の
  センチネル比較は表示より前に評価されるため現行のまま動く。

## ROM 予算 (ほぼ発動しない見込み)

フォントは ROM 上 **1bpp (8 バイト/タイル)** で保持される
(`generate_font_data_h` / `load_tiles(..., 1)`) ため、満枠 442 グリフでも
**約 3.5KB** にしかならない (14KB は VRAM 上の 4bpp 展開後の話で、
VRAM は 448 タイル分あるので問題ない)。main バンクを圧迫した場合の
待避先として font_data の **ROM バンク3** 移設 (demo07 の shou_data.c と
同じ #pragma bank + 0xFFFF 書込みパターン、demo04 は 64KB ROM 化) を
選択肢として記録するが、**1bpp 前提では当面不要の見込み**。

## エラー処理

- ビルド時: ENCODING_MAP に無い文字 → converter がエラー (現行同様)。
  グリフ予算超過 → font_builder がハードエラー + 超過一覧。
- 実行時: タイル数を超えるコード → 化けタイル表示 (現行の未知バイトと
  同等、許容)。`puts_packed` に非文字列 → エラー表示 + exit。

## テスト方針

- **Ruby 側 (minitest, TDD)**: pack_blocks のブロック形状・mask ビット
  配置・PAD 充填・制御コード符号化、font_builder の 442 グリフ予算とレポート。
- **VM 側 (ホストテストスイート)**: 既知のパック文字列を `puts_packed`
  する bytecode フィクスチャを実行し、`cursor_x`/`cursor_y` (テスト用に
  demo07 の scroll_y と同様 non-static 化) の移動と改行処理を検証。
  `op_string` の len 格納も T_STRING 値経由で検証可能。
  既存スイートは `puts` 無変更のため全て通ること。
- **受入**: 現行デッキを新パイプラインでビルドし、エミュレータで従来と
  同一表示であることを目視確認 (リポジトリ慣例)。

## 不変条件・注意

- 本 VM の文字列は常に定数プール (ROM) 直指しで、実行時生成はない。
  文字列操作機能を将来追加する場合は、新たな producer も `u.str.len` を
  正しく設定すること (これは union に長さを持たせたことで自然に守られる)。
- mask の bit i は ブロック内 i 番目 (byte 1+i) の文字に対応する。
- パック文字列は 0x00 バイトを含み得るため strcmp ベースの `op_eq` では
  比較できない。比較が必要な文字列 (センチネル・コマンド) は raw に保つ
  (ワイヤフォーマット節参照)。
