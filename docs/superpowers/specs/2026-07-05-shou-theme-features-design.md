# 「照」テーマ機能一式 設計ドキュメント

日付: 2026-07-05
対象: mrubyz (Sega Master System / Z80 上の mruby VM)

## 背景と目的

「照」をテーマにしたイベント登壇で使う機能を mrubyz 上に実装する。
既存アセットはスライドプレゼンテーション (demo04) と 1対1のインベーダー風
ミニゲーム (demo05)。8ビット機 (SMS) の制約の中で、重い演算を避けつつ
「照らす」を視覚的に見せることが目的。

成果物は次の2つ:

1. **目玉演出「照スポットライト → ホワイトアウト」** — 独立ROM (demo07)
2. **ゲーム「フラッシュ・インベーダー」** — demo05 の改修版

## 設計原則

- 光の表現はすべて **パレット (CRAM) 操作とスプライト描画の有無** で作る。
  ピクセル単位のライティング演算はしない。
- Ruby↔VM 境界で渡す値は **スカラー (int) のみ**。このVMの配列サポートは
  極小 (`size` のみ) のため、配列を境界越しに渡さない。ループ・補間・
  テーブル参照は C 側プリミティブが担当し、Ruby は薄く叩くだけ。
- 新プリミティブは `mrubyz.c` の `call_builtin()` に既存パターン通り追加し、
  非SMSビルド用スタブ (mrubyz.c 56–101 行付近のパターン) も必ず用意して
  ホスト側テストを壊さない。

## 追加する VM プリミティブ (3つ)

| 名前 | 引数 | 動作 |
|------|------|------|
| `set_colour(index, value)` | index: 0–31, value: 0x00–0x3F | CRAM の1エントリに直接書く。index 0–15 = BGパレット、16–31 = スプライトパレット。全光演出の心臓部 |
| `set_scroll(x, y)` | ピクセル座標 | 背景ハードスクロール位置を設定 (`scroll_bkg` の薄いラッパ。既存 `bg_scroll` の一般化) |
| `random(n)` | n: 上限 | 0〜n-1 の乱数を返す (C側 `rand()` の薄いラッパ。`srand` は既存の使用箇所と同様に初期化) |

いずれも戻り値・引数はスカラーのみ。`set_colour` と `set_scroll` は
VBlank 内で呼ばれる前提の軽い書き込みなので追加の同期機構は不要。

## 機能1: 目玉演出「照スポットライト → ホワイトアウト」(demo07)

会場で登壇者・観客を画面光で物理的に「照らす」ための一本道の演出。
3フェーズ構成で、すべて手動 (コントローラー) で進行する。

### アセット

- **白丸背景**: 1枚の背景絵。中心に白丸、その周囲に同心円バンドを
  描き、各バンドに別のパレットインデックス (1〜N, 最大15段) を割り振って
  焼き込む。地色は index 0。円はビルド時に PC 上で生成するので、
  Z80 側に円の計算は一切ない。既存の `scripts/png_to_sms*.rb` 路線の
  変換ツールを拡張して「中心からの距離 → パレットindex」の割付を行う。
- **「照」スプライト**: 16×16 をスプライト複数枚 (8×8 × 4) で構成。
  misaki フォントの拡大は潰れるため専用にドットを打つ。黒ストロークは
  透明 (index 0) ではなく「黒として塗った非透明 index」にして、
  白丸の上でも黒く見えるようにする。
  → **解決 (2026-07-15)**: 手打ちではなく jiskan16 (JIS X 9051-1984 の
  16×16 パターン、X.org font-jis-misc) から JIS 0x3E48 を一度だけ抽出し、
  `scripts/gen_shou_sprite.rb` にビットマップとして焼き込んだ。ビルド時の
  フォント依存なし (misaki 依存も撤去)。

### フェーズ1: 探る (スポットライト)

- 画面は暗い状態 (全バンド index = 黒)。
- 黒い「照」スプライトが D-pad に**即追従**する。
- 白丸 (背景) は `set_scroll` によるハードスクロールで「照」を
  **遅れて追従**する: 毎フレーム、白丸の現在位置を「照」の位置へ
  数ピクセルずつ寄せる。加算と大小比較のみで実装する (シフト・除算は
  使わない。demo05 で実証済みの演算の範囲内)。
- 背景スクロールは端でラップするため、移動範囲は中央寄りに
  min/max でクランプし、継ぎ目を見せない。
- **足音 (2026-07-15 追加)**: 「照」の移動中、ピコピコした足音を鳴らす。
  実装は既存 sfx パターンに合わせた C 側の `start_footstep` (PSG ch2 に
  低め 2 音 (約 250Hz / 180Hz) のごく短い矩形波ティックを交互に) を、Ruby 側から
  「実際に動いたフレーム」毎に呼ぶ。レート制限は C 側 (`start_footstep` が
  前のブリップ終了まで再トリガーを無視) に任せ、実質 2 ループフレームに
  1 歩の最大レートで鳴る。
  ホワイトアウト中 (「照」が見えない間) は鳴らさない。

### フェーズ2: 拡大 (手動送り)

- **A ボタン**を押すたびに、同心円バンドを内側から 1 段ずつ
  `set_colour(index, 白)` で点灯する。**B ボタン**で 1 段戻す (消灯)。
- 手動送りなので、登壇者のセリフ (「今、皆さんを照らしています」) に
  同期して光を広げられる。

### フェーズ3: ホワイトアウト

- 全バンド点灯後、さらに A ボタンで地色 index 0 も白へ → 画面 100% 白。
  「照」の字も白に溶ける。ここが機能C (ホワイトアウト照射) の本体。
- B ボタンの逆送りで暗転まで戻せる (次の演目に移るため)。

### フェーズ4: メッセージ表示「KANSAI RUBYKAIGI9」 (2026-07-15 追加)

ホワイトアウト完了後、A ボタンを押すたびに画面中央へ黒い
「KANSAI RUBYKAIGI9 」(スペース込み 18 文字、末尾スペース含む) を
**1文字ずつ** 表示する。

- **描画方式**: パレットではなくネームテーブル書き換え。1文字 =
  ネームテーブルのセル (7+i, 12) に 1 ワード書くだけ (`SMS_setTileatXY`)。
- **文字タイル**: build 時に `scripts/gen_shou_text.rb` が z88dk 標準フォント
  (FONT8.BIN) からメッセージ順で 17 タイル生成する。ストロークは
  BG パレット **index 15** — 円は index 0–12 しか使わず A/B も 13–15 を
  触らないため常に黒。地は index 0 なのでホワイトアウト中は白。
  VRAM は円タイルの直後 (`SHOU_CIRCLE_TILE_COUNT` 番から 17 枚、
  330+17=347 ≤ 443 で衝突なし)。
- **スクロール整合**: ホワイトアウト突入時にスクロールを (0,0) へ戻し
  (全白なので見えない)、ホワイトアウト中は追従を停止する。これで
  文字が画面中央に揃う。B で戻ると追従が再開し、光が「照」の位置へ
  滑って戻る。
- **消去**: B (ホワイトアウトから戻る操作) で文字を全消去してから暗転側へ
  1段戻る。消去は bank 2 の `shou_circle_map` から該当 17 セルの元マップ語を
  書き戻す (`SMS_loadTileMapArea`)。
- **タイプ音 (2026-07-15 追加)**: 1文字表示ごとに PSG ノイズチャンネル (ch3) で
  1 フレームのホワイトノイズ「カチャッ」(タイプライター打鍵音)。スペース
  (6文字目・末尾) は無音。末尾スペースの表示押下で ch2 に高音 (約 2kHz) の
  リングダウン「チーン」(キャリッジベル) — 「9」の打鍵音とベルが 1 押し分
  離れて鳴る。C 側 `start_type_clack` / `start_type_bell` (sfx パターン準拠、汎用)。
- **builtin は demo07 専用**: `reveal_letter(i)` / `hide_letters` を
  `mrubyz.c` の `call_builtin()` に `#ifdef SHOU_TEXT` 付きで追加し、
  demo07 のビルドだけ `-DSHOU_TEXT` を渡す。実体は demo07.c 側
  (show_logo と同じ extern パターン)。他デモへのスタブ追加は不要で、
  ホスト側テストにも影響しない。

### 置き場所

独立 ROM (demo07) として作る。動作確認後に demo04 (プレゼン本体) への
組み込みを検討する。プレゼン本体を壊すリスクを避けるための分離。

## 機能2: ゲーム「フラッシュ・インベーダー」(demo05 改修)

> **見送り決定 (2026-07-15)**: Kansai RubyKaigi 9 では実装しない。
> demo07 が「照」テーマを十分に担うこと、および demo05/demo06 が
> 「同一ゲームの VM 実行 vs AOT 実行」の対照実験として使われるため、
> demo05 だけ改修すると比較が成立しなくなることが理由。
> 将来やる場合の設計は以下に残す。

既存 demo05 のメインループ構造・操作・勝敗条件を維持したまま、
「照らして見つけて撃つ」を追加する。差分は3点のみ。

### 暗い間 (通常状態)

- 画面は暗いパレット。**敵スプライトは `put_sprite` を呼ばない**
  ことで不可視にする。
- 敵は `random` を使ってでたらめに移動する (既存の左右往復を置換)。
- **敵の弾は暗くても見える**。弾筋が敵の位置の手がかりになる
  (マズルフラッシュ的な駆け引き)。
- 自機・自弾は常に見える。

### フラッシュ (照らす)

- 画面の左右端がライトのスイッチ。ランプのスプライトを両端に
  毎フレーム `put_sprite` して見せる (背景はスクロールするため
  固定物はスプライトで描く)。
- トリガー条件と点灯は次のロジックのみ:

```ruby
if flash_timer == 0 && (player_x == 1 || player_x == 30)
  flash_timer = 60           # 点灯時間 (約1秒)
end
flash_timer -= 1 if flash_timer > 0
# flash_timer > 0 の間: 明パレット + 敵を put_sprite + 敵の移動処理をスキップ
```

- 点灯中: 明るいパレットに切り替え、敵を描画し、**敵は移動を停止する**
  (照らされてすくむ)。
- ボタン追加なし (A=撃つ のまま)、残数表示なし。ルールは画面上の
  物理配置 (端のランプ) で伝わる。
- 点灯中の再トリガーは上記 if 文で自然に抑止される。
- **端に居座ると消灯直後に再点灯し、実質連続点灯になる。これは意図した
  仕様** (端からは敵の真下に入れず攻撃機会がほぼないため、自然に
  バランスが取れる)。バグとして「修正」しないこと。

### ゲームバランス上の狙い

端 (スイッチ) と中央 (射撃位置) が両立しないため、「照らしに行く」→
「約1秒のうちに戻って撃つ」の緊張感がルール説明なしで成立する。

## 実装順序 (安い順・各段階でデモ可能)

1. **プリミティブ 3つ + 非SMSスタブ** (`set_colour`, `set_scroll`, `random`)
2. **目玉演出 demo07**: まず静的な「拡大 → ホワイトアウト」(フェーズ2–3)、
   その後スポットライト追従 (フェーズ1) を足す
3. **ゲーム改修** (demo05): 可視フラグ → フラッシュ状態機械 → 乱数移動 の順
4. **(任意・余裕があれば)** 通常ページ送り用のフラットフェード
   (パレット全体を黒→本来色へ段階補間する演出)

## テスト方針

- プリミティブ追加後もホスト側 (`make test`) の既存テストが通ることを
  確認する (非SMSスタブがあればビルドは通る)。プリミティブ単体の
  ユニットテストは必須としない — 既存フレームワークは戻り値の型しか
  検証できず、価値が薄いため。動作確認はエミュレータでの目視を主とする。
- 演出・ゲームの見た目はエミュレータでの手動確認 (既存デモと同様)。
